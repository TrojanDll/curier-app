# Инструкция по развёртыванию — Курьер SaaS

Это инструкция для **владельца сервера** — человека, который разворачивает систему у себя и раздаёт APK курьерам. Технического бэкграунда уровня «умею в SSH и Linux» достаточно.

В конце процедуры у вас будет:

- работающий backend на `http://<IP-сервера>:8081`
- работающая админ-панель на `http://<IP-сервера>:3000`
- подписанный APK для раздачи курьерам

---

## 1. Что вам понадобится

- Linux-сервер (Ubuntu 22.04+ / Debian 12+ / Rocky 9+ или похожий).
  Подойдёт и облачный VPS, и обычный домашний компьютер с публичным IP — лишь бы на нём стоял Docker.
- Минимум 2 GB RAM, 10 GB свободного места.
- Открытые входящие порты `3000` (админка) и `8081` (API для курьеров).
- Базовое умение работать с терминалом по SSH.
- Архив с проектом (или клон репозитория).

> HTTPS из коробки не входит в стек — за TLS отвечает то, что стоит перед сервером (nginx, Caddy, Traefik, Cloudflare Tunnel и т. п.). По умолчанию всё работает по HTTP.

---

## 2. Установка Docker

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
# Перелогиньтесь, чтобы группа docker применилась
```

Проверка:

```bash
docker --version              # >= 24.x
docker compose version        # >= v2.20
```

Если `docker compose version` отвечает ошибкой — поставьте plugin:

```bash
sudo apt-get install docker-compose-plugin
```

---

## 3. Распаковать проект

Положите архив на сервер и разверните в любую директорию, например:

```bash
mkdir -p /opt/curier && cd /opt/curier
tar xzf ~/curier-v2.tar.gz       # или git clone <url> .
ls
# admin/  android/  backend/  docker/  docs/  Documentation/  README.md ...
```

---

## 4. Настроить `.env`

В директории `/docker/` есть шаблон `.env.example`. Скопируйте его и впишите свои значения:

```bash
cd /opt/curier/docker
cp .env.example .env
nano .env
```

Минимум, что нужно поменять, **обязательно**:

| Переменная | Что подставить |
|---|---|
| `DB_PASSWORD` | любой надёжный пароль для БД (через который никто кроме контейнеров не ходит) |
| `JWT_SECRET` | длинная случайная строка. Сгенерируйте: `openssl rand -base64 64` |
| `INITIAL_ADMIN_USERNAME` | имя первого администратора, например `admin` |
| `INITIAL_ADMIN_PASSWORD` | его временный пароль — поменяете в админке после первого входа |

Остальное можно оставить дефолтным. Полный список переменных и их назначение — в `docs/docker-stack.md`.

> Файл `.env` не коммитится в репозиторий и не должен покидать сервер. Это ваш единственный артефакт с паролями.

---

## 5. Запустить стек

Из директории `/docker/`:

```bash
docker compose --env-file .env up -d --build
```

Что произойдёт:

1. Скачаются базовые образы (`node:22-alpine`, `postgres:16-alpine`).
2. Соберутся образы backend и admin (5–10 минут на первом запуске).
3. Поднимутся три контейнера: `db`, `backend`, `admin`.
4. Backend применит миграции БД и засеет первого администратора с логином/паролем из `.env`.

Проверьте состояние:

```bash
docker compose ps
# Должны быть три строки со статусом "Up" или "Up (healthy)".

curl http://localhost:8081/health
# {"status":"ok"}

curl -I http://localhost:3000/
# HTTP/1.1 307 ...  (редирект на /login — это нормально)
```

Логи:

```bash
docker compose logs -f                       # все сервисы
docker compose logs -f backend               # только backend
```

## 6. Первый вход в админку

Откройте в браузере: `http://<IP-сервера>:3000`

Войдите с `INITIAL_ADMIN_USERNAME` / `INITIAL_ADMIN_PASSWORD` из `.env`.

**Сразу же** поменяйте пароль:

1. Откройте «Настройки» в админке.
2. Раздел «Смена пароля».
3. Введите текущий пароль и новый. После смены все старые refresh-токены отзываются автоматически.

Дальше — см. [ADMIN_USER_MANUAL.md](ADMIN_USER_MANUAL.md): как заводить курьеров, создавать заказы, настраивать TTL фото и контакт поддержки.

## 7. Раздать APK курьерам

В архиве лежит подписанный APK курьерского приложения (если вы собирали его сами — см. [android-release-build.md](android-release-build.md)). Файл `app-release.apk` весит около 7 MB.

Раздача:

1. Скиньте `.apk` курьеру через Telegram / WhatsApp / Viber / по почте.
2. Курьер скачивает файл, разрешает установку из неизвестных источников (один раз) и устанавливает.
3. При первом запуске приложение попросит ввести **адрес сервера**. Скажите курьеру что вводить — это `http://<IP-вашего-сервера>:8081`.
4. Курьер вводит логин и пароль, которые вы создали ему в админке.

Подробнее — в [COURIER_USER_MANUAL.md](COURIER_USER_MANUAL.md).

## 8. Бэкапы

### Способ 1 — через админку (рекомендуется)

В админ-панели есть раздел **Бэкапы** (см. [ADMIN_USER_MANUAL.md](ADMIN_USER_MANUAL.md) §7). Администратор одной кнопкой делает бэкап **всех** данных (БД + фото) в один ZIP, скачивает его, хранит историю, восстанавливается из любого бэкапа и импортирует/экспортирует архивы — без доступа к серверу и Docker.

Это основной способ для владельца бизнеса. **Скачивайте архив и храните его вне сервера** (другой диск, облако) — тогда вы защищены и от потери всей машины.

Сами бэкапы лежат в отдельном volume `docker_backups` (history переживает обновления стека и `docker compose down`, но не `down -v`).

### Способ 2 — копия томов off-box (для катастроф)

Где физически живут данные:

| Что | Где (docker volume) | Что в этом |
|---|---|---|
| База данных | `docker_db_data` | таблицы (заказы, курьеры, фото-метаданные, ...) |
| Фото доставок | `docker_uploads` | сами файлы `.jpg` |
| Архивы бэкапов | `docker_backups` | ZIP-бэкапы из админки + их история |

**Минимальная off-box копия раз в сутки** (cron / systemd timer) — на случай потери всей машины:

```bash
docker run --rm \
  -v docker_db_data:/data \
  -v /var/backups/curier:/backup \
  alpine tar czf /backup/db-$(date +%F).tgz -C /data .

docker run --rm \
  -v docker_uploads:/data \
  -v /var/backups/curier:/backup \
  alpine tar czf /backup/uploads-$(date +%F).tgz -C /data .

# Архивы, сделанные через админку (чтобы не потерять и их):
docker run --rm \
  -v docker_backups:/data \
  -v /var/backups/curier:/backup \
  alpine tar czf /backup/backups-$(date +%F).tgz -C /data .
```

Восстановление — обратная операция (`tar xzf ...` в чистый volume), пока компоуз остановлен.

Реальная катастрофа: потеря `db_data` ≈ потеря всей истории заказов и курьеров. Потеря `uploads` ≈ потеря фото (заказы и метаданные останутся в БД, картинки пропадут).

## 9. Обновление до новой версии

> Перед обновлением сделайте бэкап (см. §8 — проще всего через админку, раздел **Бэкапы**).

1. Сохраните `.env` в стороне (он не меняется между версиями).
2. Распакуйте новую версию репозитория поверх старой (или `git pull`).
3. Перезапустите стек:

   ```bash
   cd /opt/curier/docker
   docker compose --env-file .env up -d --build
   ```

4. Миграции БД применятся автоматически при старте backend (через `prisma migrate deploy`).

Без `down -v` данные не теряются — вы просто перезаписываете образы.

## 10. Остановка и удаление

```bash
docker compose down            # остановить, данные сохраняются
docker compose down -v         # остановить + удалить volumes (БД и фото) — НЕОБРАТИМО
```

## 11. Возможные проблемы

| Симптом | Что делать |
|---|---|
| `docker compose ps` показывает backend в `Restarting` | Посмотрите `docker compose logs backend` — обычно это либо неправильный `DATABASE_URL`, либо проблема с миграцией. Проверьте, что `DB_PASSWORD` в `.env` не содержит spec-символов без экранирования. |
| Курьерское приложение пишет «Не удалось подключиться» | Проверьте: 1) backend поднят (`curl http://<IP>:8081/health`), 2) порт 8081 открыт во firewall, 3) курьер ввёл `http://`, а не `https://`. |
| Админка пишет «401 Unauthorized» сразу после входа | refresh-токены откатились (например, после смены пароля). Перезайдите. Если повторяется — `docker compose logs admin` и `docker compose logs backend`. |
| Порт `3000` или `8081` занят на сервере | В `.env`: `BACKEND_PORT=18081`, `ADMIN_PORT=13000` (или любые свободные). |
| Хочется поставить SSL/HTTPS | Поставьте перед стеком nginx / Caddy / Traefik и оформите reverse-proxy с TLS. Сам стек оставайтся HTTP внутри. |

Глубже про сам стек, healthcheck-и, env-переменные и troubleshooting — см. [docker-stack.md](docker-stack.md).
