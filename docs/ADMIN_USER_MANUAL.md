# Руководство администратора — Курьер SaaS

Эта инструкция — для **администратора**, который через веб-панель создаёт курьеров, заводит заказы и следит за работой службы.

Адрес панели — обычно `http://<IP-сервера>:3000` (если у вас настроен домен и HTTPS — соответственно ваш URL).

---

## 1. Вход в систему

1. Откройте `http://<IP-сервера>:3000` — вас перенаправит на `/login`.
2. Введите логин и пароль администратора.

При первом входе используйте логин/пароль, которые владелец сервера задал в `.env` (см. `DEPLOYMENT.md`). **Сразу же** смените пароль через раздел «Настройки» (см. §6).

Сессия живёт 30 дней (refresh-токен в HttpOnly cookie). Если вас выкинуло на /login — токен истёк, авторизуйтесь заново.

---

## 2. Что есть в панели

| Раздел | Зачем |
|---|---|
| **Заказы** | Создание новых, фильтрация по статусу / курьеру, переназначение курьера |
| **Курьеры** | Создание, редактирование, отправка домой / возврат на смену, смена пароля, увольнение |
| **Статистика** | Сводка по доставкам — общая + разбивка по курьеру, период (сегодня / неделя / месяц / свой диапазон) |
| **Бэкапы** | Резервные копии всех данных: создать, скачать (ZIP), история, восстановление, импорт/экспорт |
| **Настройки** | TTL для фото доставок, контакт поддержки (виден курьерам), смена пароля админа |

Внизу слева — карточка текущего админа и кнопка выхода.

## 3. Заведение курьеров

Раздел **Курьеры → Создать**.

Обязательные поля:

| Поле | Что вводить |
|---|---|
| Логин | латиница / цифры, ≥3 символа. Курьер будет вводить его при входе. |
| Пароль | ≥6 символов. Передайте курьеру лично или мессенджером. |
| ФИО | для отображения в админке и в приложении курьера |

Опциональные: email, телефон, дата рождения. Email/телефон курьер может потом изменить сам через свой профиль; ФИО и дату рождения — только админ.

После создания курьер сразу может зайти в приложение и работать. По умолчанию у курьера статус «активен, на смене».

### Управление существующими курьерами

| Действие | Когда применять | Что делает |
|---|---|---|
| **Редактировать** | поменялось ФИО, email, телефон или дата рождения | PATCH с новыми значениями |
| **Отправить домой** | курьер закончил смену / заболел / в отпуске | новые заказы ему не назначаются. Текущие активные заказы остаются. Курьер видит в приложении баннер «Вы не на смене» |
| **Вернуть на смену** | вернулся в строй | очередь ожидающих заказов пересчитывается, ему может тут же прилететь свободный |
| **Сменить пароль** | курьер забыл свой / скомпрометирован | вы вводите новый, все его старые сессии (включая запущенное приложение) разлогиниваются |
| **Уволить** | курьер больше не работает у вас | мягкое удаление. Заказы за ним остаются в истории. Залогиниться больше не сможет |

Уволенного курьера обратно не восстановить через UI — это намеренно. Если действительно нужно — создайте заново.

## 4. Заказы

### Создание

Раздел **Заказы → Новый заказ**. Поля:

| Поле | Что вводить |
|---|---|
| Имя клиента | как звать получателя |
| Телефон клиента | для звонка/SMS курьером |
| Адрес доставки | полный адрес — курьер сможет открыть его в Картах |
| Описание товара | что доставлять (для курьера) |
| Цена | сумма (видна только админу, курьеру не показывается) |
| Комментарии | необязательно (например, «домофон не работает, звонить в звонок») |

После сохранения заказ автоматически назначается курьеру по алгоритму «дольше всех на базе»:
- если есть свободные курьеры (активные, на смене, без текущего заказа) — берётся тот, кто дольше всех ждёт;
- если все заняты — заказ остаётся со статусом `new` и автоматически уйдёт первому освободившемуся.

### Фильтрация и поиск

В таблице заказов:
- **Статус** — chip-фильтр (все / активные / завершённые / new).
- **Курьер** — выпадающий список активных курьеров.
- **Поиск** — по номеру заказа / адресу / имени клиента (с задержкой 300 мс).
- **Пагинация** — по 10 заказов на страницу.

### Переназначение курьера

Откройте заказ → блок «Курьер» → выберите другого курьера из списка.

Доступно только для статусов `new` и `assigned` — после того как курьер начал забирать товар (`picked_up`), переназначить нельзя. Курьеры, отмеченные как «дома», и текущий владелец заказа в списке не показываются.

### Фото доставки

Если курьер сделал фото — оно появится в карточке заказа. Кликните на превью — откроется в lightbox. Фото хранятся ограниченное время (см. §6); автоматически удаляются по истечении TTL.

### Жизненный цикл заказа

```
new → assigned → picked_up → near_customer → delivered → returned
```

| Статус | Что значит |
|---|---|
| `new` | заказ создан, курьер ещё не назначен (нет свободных) |
| `assigned` | назначен курьеру, ждём, пока тот заберёт |
| `picked_up` | курьер забрал товар у вас |
| `near_customer` | курьер у клиента |
| `delivered` | передал клиенту, едет назад |
| `returned` | вернулся на базу, готов брать следующий заказ |

Откатывать статусы назад нельзя — это намеренно, защита от случайных нажатий курьером.

## 5. Статистика

Раздел **Статистика**.

Сверху — выбор периода:

- **Сегодня** / **Неделя** / **Месяц** — пресеты
- **Свой диапазон** — указать from и to

Карточки KPI:
- Всего доставок (статус delivered + returned)
- Возвратов (return)
- Средняя длительность доставки
- Активные курьеры (которые в работе сейчас)

График — динамика количества доставок во времени (для «сегодня» — по часам, для «недели» — по дням, для «месяца» — по дням, для свободного диапазона — авто-bucket).

Таблица **Разбивка по курьерам** — статистика на каждого: доставок, возвратов, среднее время. Сортируется по любому столбцу.

Цифры обновляются при каждом открытии страницы (без realtime — обновите вручную).

## 6. Настройки

### Хранение фото

Поле «TTL фото (дней)» — от 1 до 365. Применяется к **новым** загрузкам: уже сохранённые фото остаются с тем сроком, который был на момент загрузки. Менять TTL ретроактивно нельзя — это безопаснее (фото, на которые курьер мог сослаться, не пропадают неожиданно).

После сохранения TTL применяется сразу — следующая фото-загрузка пойдёт с новым сроком.

### Контакт поддержки

Свободный текст до 500 символов. Курьеры видят его в своём приложении на экране «Профиль → О приложении → Поддержка». Сюда можно положить:

- Имя диспетчера + телефон: `Иван Петров, +7 999 123-45-67`
- Telegram-аккаунт: `@dispatcher_support`
- Email: `support@curier.example`
- Любой комбинированный текст

Курьерское приложение само распознаёт телефоны, email и URL в этом тексте и делает их тапаемыми ссылками — курьер сразу позвонит / напишет.

Если поле пустое — курьер видит фразу «По вопросам работы с приложением свяжитесь с администратором вашей компании.».

### Смена пароля админа

Минимум 8 символов. Новый пароль не должен совпадать с текущим. После успешной смены backend отзывает все ваши refresh-токены — это значит, что любые другие открытые сессии (другая вкладка / устройство) разлогинятся при следующем запросе. Текущая вкладка живёт до истечения короткого access-токена (по умолчанию 15 минут), потом тоже попросит ввести пароль.

## 7. Бэкапы

Раздел **Бэкапы** — резервные копии всех данных системы. Один бэкап — это единый ZIP-архив, в который входят: все заказы, курьеры, настройки и фотографии доставок.

### Создать бэкап

Кнопка **«Создать бэкап»**. По желанию впишите заметку (например, «перед обновлением») — она будет видна в истории. Через несколько секунд бэкап появится в списке ниже.

> Полезная привычка: делайте бэкап **перед обновлением сервера** и перед любыми массовыми изменениями.

### Скачать / экспортировать

В строке бэкапа — кнопка **«Скачать»**. Архив сохранится на ваш компьютер. Это же и есть экспорт: храните такой ZIP отдельно (на другом диске, в облаке) — он не зависит от сервера и его можно потом загрузить обратно.

### История

Таблица показывает все бэкапы (свежие сверху): дату, тип, содержимое (сколько заказов / курьеров / фото), размер и кто создал. Типы:

| Тип | Что это |
|---|---|
| **Ручной** | вы нажали «Создать бэкап» |
| **Импорт** | загружен из файла |
| **Авто-снимок** | система сделала автоматически — перед восстановлением (чтобы можно было откатиться) |

### Восстановление

Кнопка **«Восстановить»** в строке бэкапа **полностью заменяет** текущие данные данными из этого бэкапа.

Что важно знать:

- Перед заменой система **автоматически создаёт снимок** текущего состояния — если что-то пойдёт не так, к нему можно вернуться (он появится в истории как «Авто-снимок»).
- Восстановление **сбрасывает все сессии**: возможно, вас выйдет из системы и придётся войти заново. Для входа после восстановления ваш администраторский аккаунт должен присутствовать в выбранном бэкапе.
- Делайте восстановление в спокойное время, когда курьеры не работают активно.

Перед запуском панель показывает предупреждение — подтвердите его, чтобы продолжить.

### Импорт

Кнопка **«Импортировать из файла»** — загрузите ранее скачанный ZIP-бэкап. Он добавится в историю (как «Импорт»), после чего из него можно восстановиться. Так данные переносятся между серверами или возвращаются из внешнего хранилища.

### Удаление

Кнопка с корзиной удаляет бэкап из истории безвозвратно. Сами данные системы при этом не меняются — удаляется только архив.

## 8. Live-обновления

Когда вы держите админку открытой, она получает события через WebSocket:

- новый заказ создан / переназначен → таблица заказов обновляется без F5;
- курьер отправлен домой / вернулся на смену → бэдж в карточке курьера меняется сам;
- курьер сменил статус заказа → строка в таблице тоже.

Если соединение разорвалось — иконка статуса в углу станет жёлтой/красной, страница продолжит работать на пуллинге, при восстановлении — снова realtime.

## 9. Раздача APK курьерам

Сам APK админка не раздаёт — это делает владелец сервера (через мессенджер, ссылку, USB и т. п.). Ваша задача:

1. Заведите курьеру логин/пароль (см. §3).
2. Отдайте курьеру:
   - адрес сервера (например, `http://203.0.113.10:8081`),
   - его логин и пароль,
   - ссылку на [COURIER_USER_MANUAL.md](COURIER_USER_MANUAL.md), если нужны подробности.
3. APK ставится на телефон один раз; обновления приходят отдельно — заменой файла.

## 10. Что делать, если…

| Ситуация | Решение |
|---|---|
| Курьер потерял пароль | Курьеры → найти → «Сменить пароль», ввести новый, передать |
| Курьер уволился | Курьеры → найти → «Уволить». Если потом вернётся — создавайте заново |
| Заказ повис в `new`, не назначается | Все активные курьеры либо дома, либо с активным заказом — верните кого-то на смену или дождитесь возврата |
| Хочу удалить заказ | Заказы не удаляются — это история. Если создан по ошибке, переведите его на курьера с тестовым статусом или попросите курьера откатить (он сам не может) |
| Фото просрочилось до того как я его посмотрел | Поднимите TTL в Настройках. На уже удалённые ретроспективно не действует |
| Цифры в статистике не сходятся | Проверьте, что выбранный период не урезан фильтрами по курьеру; обновите страницу |
| Боюсь потерять данные / собираюсь обновлять сервер | Зайдите в **Бэкапы → Создать бэкап** и скачайте архив (§7). Восстановиться можно там же |
| Случайно испортил данные | **Бэкапы → Восстановить** из подходящего бэкапа. Перед заменой система сама делает авто-снимок (§7) |

Если что-то совсем не работает — соберите логи (`docker compose logs backend` / `docker compose logs admin` на сервере) и передайте владельцу сервера.
